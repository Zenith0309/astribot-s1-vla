# Astribot S1 · pi0.5 微调完整指南

从数据采集到部署评测，打通 Astribot S1 人形机器人 pi0.5（Vision-Language-Action）模型微调的完整链路。本文覆盖**真机遥操作采集 → 标注 → 格式转换 → 归一化 → 训练 → 推理服务 → 闭环评测**，并汇总官方框架的一批隐藏坑与解法。

> 适用：已获得 `astribot_pi05` 训练框架与 `pi05_base_bfloat16` 预训练权重（向 support@astribot.com 申请）的团队。
> 说明：文中路径用 `<占位符>` 表示，按自己环境替换。命令均在项目实测跑通。

## 1. 总览与架构

pi0.5 是 PaliGemma（视觉-语言）+ Gemma Expert（动作）的双模型架构，动作空间为**全身 34 维笛卡尔 SO3**。微调链路：

```
真机遥操作采集 ──> 原始 HDF5（官方格式，含底盘/力矩/三相机）
                        │
                  标注（语言指令 + 成功标签）
                        │
        convert_hdf5_to_lerobot ──> LeRobot 数据集（笛卡尔 SO3 + 视频）
                        │
              compute_norm_stats ──> norm_stats.json
                        │
                   train.sh ──> checkpoint（含 processor + 权重）
                        │
        ┌───────────────┴───────────────┐
   serve_policy（推理服务, WebSocket）        │
        │                              评测客户端
   真机 astribot_eval / 仿真评测 ──> 成功率
```

**关键前提：数据是一切。** 模型能否学会取决于数据的**任务一致性**与**分布多样性**——物体位置、初始条件必须充分随机化，否则模型会走"记忆平均动作"的捷径而忽略视觉（因果混淆，见 [第 11 节](#11-已知坑与解法)）。

## 2. 环境搭建

训练环境独立于机器人控制环境（避免 PyTorch 版本冲突）。

```bash
# Python 3.11 + CUDA 12.1+（推荐 12.4）
conda create -n astribot_pi05 python=3.11 -y && conda activate astribot_pi05
cd <astribot_pi05 仓库>/astribot_pi05
bash install.sh          # 装 torch2.7 + transformers 补丁 + flash-attn（尽量装上，省显存）
```

**境内网络两项必做：**

1. **tokenizer 离线化**。训练/推理要加载 `google/paligemma-3b-pt-224` 的 tokenizer，境内直连 HuggingFace 常超时。从魔搭下载后指向本地：

   ```bash
   pip install modelscope -i https://mirrors.aliyun.com/pypi/simple/
   python3 -c "from modelscope import snapshot_download; print(snapshot_download('AI-ModelScope/paligemma-3b-pt-224', allow_patterns=['tokenizer*','*.json','special_tokens*']))"
   # 把打印的目录填进 processor（processor_pi05.py 里 GemmaTokenizer.from_pretrained 那行），
   # 训练/推理时 export HF_HUB_OFFLINE=1
   ```

2. **ffmpeg**（视频编码要用，转换与训练都依赖）：

   ```bash
   conda install -n astribot_pi05 -c conda-forge ffmpeg -y
   ```

## 3. 数据采集

### 3.1 任务设计原则

- **单批一个任务**。一批数据对应一个明确任务（如 "pick up the red cube and put it in the box"）。多任务分批采、或用逐段标注（[第 4 节](#4-数据标注)）。
- **充分随机化**。每条 episode 换物体位置、初始姿态、光照等。分布越窄，模型越容易忽略视觉去背平均动作。**这是模仿学习最常见的失败根因**，务必重视。
- **数据量**。单任务微调建议 ≥ 50 条成功演示，100+ 更稳。

### 3.2 遥操作采集

用官方 `astribot_eval/tools` 的遥操作工具（VR / 手柄）完成任务，每条录一个原始 HDF5。采集时机器人本体电脑运行官方采集链路。

### 3.3 原始 HDF5 格式

官方采集产出的 HDF5 结构（关键部分）：

| 组 / 键 | 形状 | 含义 |
|---|---|---|
| `poses_dict/astribot_<部件>` | (T,7) | 各部件**实际**笛卡尔位姿（xyz + 四元数） |
| `command_poses_dict/astribot_<部件>` | (T,7) | 各部件**指令**位姿 |
| `joints_dict/joints_position_state` | (T,25) | 关节实际位置（含底盘 3 + 头部 2） |
| `joints_dict/joints_position_command` | (T,25) | 关节指令位置 |
| `images_dict/{head,left,right}/rgb` | (N,) | 拼接 JPEG 字节流 |
| `images_dict/{head,left,right}/rgb_size` | (T,) | 每帧 JPEG 字节数 |
| `endpoint_wrench_dict/*` | (T,6) | 末端力/力矩 |
| attrs `episode_success` | - | 成功标签（可选，见 4.3） |

## 4. 数据标注

官方 `convert_hdf5_to_lerobot` 有两种标注模式。**语言指令**是 episode 级（或逐段），**成功标签**在 HDF5 attr。

### 4.1 模式 A：整批一个任务（推荐，零标注量）

单任务重复采集用这个——`--coarse-prompt` 给一句话，对所有帧写同一 prompt，不需要任何标注文件：

```bash
python3 -m pi05.tools.convert_hdf5_to_lerobot \
  --raw-path <raw_dir> --output-path <out> --dataset-name my_task \
  --coarse-prompt "pick up the red cube and put it in the box" \
  --fps 30 --robot-type S1-stationary
```

### 4.2 模式 B：逐段标注（多任务 / 子任务）

不给 `--coarse-prompt`，转换器会去 `raw_path/Labels/` 找 JSON 标注（Label-Studio 风格：`videoFrameTool` 打关键帧 + `textTool` 写整段 coarse prompt）。每个关键帧标 `Arm`/`Object`/`Action` 三属性，转换器用内置 `ACTION_DICT`（`grab→"pick up the {}"`、`place→"place the {}"` 等）自动拼 fine prompt。适合长程 / 多子任务演示。

### 4.3 成功标签

成功标签不在 JSON，而在 HDF5 attr **`episode_success`**（转换器 `get_episode_success_flag` 读它：>0 记成功，默认 1）。两种做法：

- **筛选式（简单）**：只留成功演示，不设 attr（默认全成功），失败的直接删源文件。
- **显式标注**：审查后给每条写 attr：

  ```python
  import h5py
  with h5py.File(path, "r+") as f:
      f.attrs["episode_success"] = 1   # 或 0
  ```

## 5. 数据审查与筛选

转成 MCAP 在 [Foxglove](https://foxglove.dev) 里逐条审查（三相机画面、关节曲线），把抓空/滑落/异常的删掉。本仓库提供 `convert/official_hdf5_to_mcap.py`：

```bash
pip install mcap h5py numpy opencv-python
python convert/official_hdf5_to_mcap.py --src <raw_dir> --out ./mcap
# Foxglove 打开 .mcap：/camera/head|left|right 看画面，/joints/state 画关节曲线
```

对模仿学习，"标注是否完成"本质上就是**筛选出成功演示**——留下的即成功集。

## 6. 转换为 LeRobot 格式

用官方转换器（[4.1](#41-模式-a整批一个任务推荐零标注量) 命令）。它做三件事：写 prompt 到 HDF5 → 逐帧组装 34 维 SO3 → 编码视频。

**动作空间是 34 维**（见[附录](#附录34-维-so3-动作空间布局)）：`torso9 + left_arm9 + left_gripper1 + right_arm9 + right_gripper1 + head2 + chassis3`。其中位姿段由 `xyz_quat_to_so3` 把 7 维（xyz+四元数）转 9 维 SO3；head 取关节最后 2 维，chassis 取关节前 3 维。**底盘天然在动作里**——真机数据训出的模型本就会协调底盘运动，无需改框架。

产出目录结构：`<out>/<dataset_name>/lerobot_so3_data_30hz/`，含 `meta/`（info.json / episodes.jsonl / tasks.jsonl）、`data/`（parquet）、`videos/`（mp4）。

## 7. 计算归一化统计

训练前必需。归一化路径按**配置文件名**派生，`compute_norm_stats` 与 `train` 必须用**同名配置**。

```bash
export HF_HUB_OFFLINE=1
bash scripts/train/compute_norm_stats.sh -c configs/train_example/<你的配置>.yaml
```

生成 `<normalization_base_path>/<配置名>/.../norm_stats.json`。建议 `normalization_base_path` 用**绝对路径**，避免 compute 与 train 工作目录不同导致找不到（见 [第 11 节](#11-已知坑与解法)）。

## 8. 训练

### 8.1 配置要点

```yaml
model_name_or_path: "<解压后的 pi05_base_bfloat16 目录>"
attn_implementation: "flash_attention_2"    # 没装 flash-attn 改 "eager"
torch_dtype: "bfloat16"

model_kwargs:
  chunk_size: 32
  freeze_vision_encoder: true      # 小数据集冻结防过拟合
  train_expert_only: true          # 只训动作 expert；显存紧张必开
  GPU_memory_opt_level: 1          # 显存不足设 2（gradient checkpointing）

processor_kwargs:
  normalization_mode: {state: "quantile", actions: "quantile"}
  normalization_base_path: "<绝对路径>/norm"

robot_datasets:
  - repo_id_list: [["lerobot_so3_data_30hz", 0.9]]   # 90%训/10%验
    dataset_root: "<数据集上级目录>"

deepspeed: "configs/deepspeed/zero2.json"     # 多卡；单卡可注释
max_steps: 30000
save_steps: 2000                              # 多留 checkpoint 便于挑选
save_total_limit: 8
```

### 8.2 显存与多卡

| 硬件 | 策略 |
|---|---|
| 单卡 80G（A100/H100） | 全参微调可行 |
| 多卡 4090/3090（24G×N） | ZeRO-2 分片，`train_expert_only=true`，per-device batch 2，梯度累积凑有效 batch |
| 单卡 24G | 极限：冻主干 + opt_level 2 + batch 1 + flash-attn，仍可能 OOM |

flash-attn 是省显存关键；24G 上没有它基本 OOM。

### 8.3 启动

```bash
export HF_HUB_OFFLINE=1
nvidia-smi                             # 挑空闲卡
export CUDA_VISIBLE_DEVICES=0,1,2,3    # -n 卡数须与此一致

# 先小步验证（200 步不 OOM、loss 下降）——注意 max_steps 要写进配置，命令行覆盖无效
bash scripts/train/train.sh -c configs/train_example/<配置>.yaml -n 4

# 正式训练挂后台
nohup bash scripts/train/train.sh -c configs/train_example/<配置>.yaml -n 4 > train.log 2>&1 &
```

checkpoint 落在 `<output_dir>/<配置名>/checkpoint-*/`。**小数据集勿训过头**——loss 很快降到很低是过拟合信号，用中间 checkpoint（评测挑最优），不要默认取最后一步。

## 9. 推理服务

```bash
export HF_HUB_OFFLINE=1; export CUDA_VISIBLE_DEVICES=0
# infer 配置：checkpoint 指向某个 checkpoint-XXXXX 的绝对路径；server_type: "sync"
bash scripts/infer/infer.sh -c configs/infer_example/<配置>.yaml
```

监听 `ws://0.0.0.0:8000`。**评测用 `server_type: "sync"`**（单客户端顺序推理，协议简单）；`async` 是为真机高频部署的 RTC 双流架构，评测客户端要另写。

## 10. 闭环评测

推理服务起好后，评测客户端组装观测发过去、收 action chunk 执行。观测协议（msgpack + WebSocket）：

- `cartesian_so3_dict.cartesian_pose_state`：**34 维**（含 chassis）
- `images_dict.head.rgb` / `left_wrist.rgb` / `right_wrist.rgb`：**CHW float[0,1]**（与训练 LeRobot 输出一致，不是 HWC uint8）
- `prompt`：任务字符串

**真机评测**用官方 `astribot_eval`（自带 250Hz 执行 + WBC/IK + 安全层）。仿真评测需自写客户端把模型输出的 SO3 动作经 IK 转关节下发（参考本仓库 `eval/pi05_eval_client.py`）。真机部署务必：动作限幅、异常自动急停、人在急停按钮旁。

## 11. 已知坑与解法

微调链路实测踩过并解决的坑，按环节归类：

**环境 / 网络**
- tokenizer 下载超时 → 魔搭下载 + 指向本地 + `HF_HUB_OFFLINE=1`。
- 视频编码 `No such file: ffmpeg` → conda 装 ffmpeg。

**转换（自采/自写转换时）**
- `add_frame() missing 'tasks' and 'coarse_task'` → 官方 fork 的 lerobot 签名是 `add_frame(frame, tasks:list, coarse_task:str)`。
- `save_episode` 空 buffer（np.stack empty）→ fork 新增 `sub_task_index`(shape 2) 特征，`add_frame` 不自动填，需在 frame 里补 `[t, T-1-t]`（单任务即整条 episode）。
- `create()` 报目录已存在 → 每次重跑先删输出目录（`exist_ok=False`）。
- `consolidate` 崩在 `load_images` 属性 → `create()` 构建的 dataset 缺该属性；用 `consolidate(run_compute_stats=False)`（pi05 有自己的 norm，不需要 lerobot 内置 stats）。

**训练**
- 归一化路径找不到 → compute 与 train 工作目录不同导致相对路径错位；`normalization_base_path` 用绝对路径，且两步用同名配置。
- `lm_head.weight newly initialized` 警告 → 正常，base 权重不含语言模型头，微调会训它。
- 命令行 `--max_steps` 不生效 → 该版本 main.py 不接受覆盖参数，改写进配置文件。

**评测**
- 视觉编码器 `expected 3 channels, got 224` → 图像要发 **CHW** 不是 HWC。
- `State dimension 31 does not match output_config dimension`（34）→ state 要发 **34 维**（末尾补 chassis 3 维）。
- 客户端连上但不动 → `server_type` 是 async；评测改 sync。
- ROS 侧客户端卡 `wait_ready` → 终端没 `source env.sh`（ROS_DOMAIN_ID 不对）。

**方法层面（最重要）**
- **因果混淆 / 记忆平均动作**：模型忽略视觉、对所有场景做同一个动作。根因是数据分布太窄 + 初始姿态固定 + 过拟合。解法：**加大物体/场景随机化范围、增加数据量、选中间 checkpoint**。这是模仿学习的核心陷阱，不是代码 bug。

## 附录：34 维 SO3 动作空间布局

`cartesian_so3_dict.cartesian_pose_state` / `cartesian_pose_command` 布局（官方固定）：

| 段 | 索引 | 维度 | 内容 |
|---|---|---|---|
| torso | 0:9 | 9 | SO3 位姿（xyz + 旋转矩阵前两行 6D） |
| left_arm | 9:18 | 9 | SO3 位姿 |
| left_gripper | 18:19 | 1 | 标量 |
| right_arm | 19:28 | 9 | SO3 位姿 |
| right_gripper | 28:29 | 1 | 标量 |
| head | 29:31 | 2 | yaw / pitch 关节 |
| chassis | 31:34 | 3 | x / y / yaw |

SO3 编码：`matrix_to_so3(R) = R[:2, :].reshape(6)`（旋转矩阵前两行展平）；`xyz_quat_to_so3` 把 7 维位姿转 9 维。训练时 delta 与坐标系变换由 processor 内部处理，数据侧只存 base 系绝对位姿。
